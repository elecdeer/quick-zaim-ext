# フェーズ3 設計: 台帳の Web 画面

## 目的

Zaim の画面で見ていたもの（月ごとの集計、記録の一覧と修正、口座の残高）を台帳の Web 画面で見られるようにする。拡張機能で登録を間違えたときも、ここで直せるようにする（TASKS.md の「ミスリカバリー」の代わり）。

最初に作るのは次の 3 つ。

1. 月ごとの集計
2. 取引の一覧と編集
3. 口座の残高

## 前提

- 同じ Worker `quick-ledger` で動かす。Cloudflare Access の後ろにあるので、画面にもログインの処理は要らない（`middleware/02.access.ts` が `accessUser` を設定する）
- 利用者は自分だけ。スマートフォンのブラウザでも見るので、狭い幅でも崩れないようにする
- 取引の数は 3,600 件ほど、月に 100 件前後。1 か月分なら一覧を一度に出してもよい

## 仕組み

Void の Pages（`pages/`）を使う。`pages/` はスパイクで作ったトップページがすでにある。

- 表示するデータはページの `.server.ts` の `loader` で D1 から読む。拡張機能向けの `/api/*` は通さない
- 変更はページの `actions`（名前付きアクション）で受ける。入力は valibot のスキーマで `defineHandler.withValidator` を使って検証する。Void はページのアクションを同じオリジンからしか受け付けないので、拡張機能の CORS とは関係しない
- 画面の移動は Void の `Link` と `useRouter` で行う。条件の切り替え（月・口座など）は URL のクエリにして、再読み込みや共有で同じ画面に戻れるようにする
- 集計・残高・一覧の SQL は `src/ledger/` に関数として置き、`db/testing.ts` のテスト用の DB でユニットテストを書く。ページの `loader` はそれを呼ぶだけにする

### UI 部品

拡張機能と同じ shadcn（base-ui 版、`base-nova`）と Tailwind CSS v4 を使う。

- `apps/ledger` に `components.json` を置き、必要な部品を shadcn の CLI で `src/components/ui/` に入れる。拡張機能の部品とは共有のパッケージにしない。拡張機能の部品はサイドパネルの狭い幅に合わせて直しているので、そのまま使い回せないため
- グラフのライブラリは入れない。カテゴリごとの割合は横棒（幅を割合にした要素）で出す

## 画面

### 共通のレイアウト（`pages/layout.tsx`）

- 上部にナビゲーション：集計 / 取引 / 口座
- 右上にログイン中のメールアドレスとログアウト（`/logout`）

### 月ごとの集計（`/`）

`/?month=YYYY-MM`。`month` がなければ今月（日本時間）。

- 前の月・次の月へ移る
- 月の合計：支出・収入・収支（収入 − 支出）
- 支出のカテゴリ別：カテゴリごとの合計と割合を多い順に並べ、開くと内訳ごとの合計が出る
- 収入のカテゴリ別：カテゴリごとの合計
- カテゴリや内訳を押すと、その条件で絞り込んだ取引の一覧へ移る

集計のきまり：

- 支出は `mode = 'payment'`、収入は `mode = 'income'` の取引の品目の金額を合計する。振替と残高調整は入れない
- `aggregation` が `always` の取引だけを入れる。`never`（集計に含めない）と `yearly_only`（年の集計にのみ含める）は月の集計に入れない。年の集計の画面は今回は作らない
- 品目の金額は符号付きなので、値引きの品目はそのまま差し引かれる
- カテゴリのない品目は「未分類」にまとめる

### 取引の一覧（`/transactions`）

`/transactions?month=YYYY-MM&mode=&accountId=&categoryId=&genreId=&placeId=`。`month` は必須にし、なければ今月。

- 1 か月分の取引を日付の新しい順に出す（同じ日は `id` の新しい順）。ページ送りは月の切り替えで代える
- 1 行に：日付、種類（支出・収入・振替・残高調整）、口座（振替は「元 → 先」）、店舗、品目（1 件ならその名前、複数なら「最初の品目名 ほか N 件」）、カテゴリ、合計金額、集計に含めない取引の印
- 絞り込み：種類・口座・カテゴリ・内訳・店舗。条件はクエリに入れる。カテゴリ・内訳は「その品目を 1 つでも含む取引」で絞る
- 絞り込んだときの合計金額を一覧の上に出す（支出と収入は分けて足す）
- 行を押すと編集画面へ移る

### 取引の編集（`/transactions/[id]`）

1 件の取引の全項目を直す・消す。

- 共通：日付、集計の設定
- 種類ごとの項目：

  | 種類     | 口座                 | 店舗 | 品目                                                           |
  | -------- | -------------------- | ---- | -------------------------------------------------------------- |
  | 支出     | 支払元               | あり | 複数。内訳（親のカテゴリは内訳から決まる）・品目名・メモ・金額 |
  | 収入     | 入金先               | あり | 1 件。カテゴリ・メモ・金額                                     |
  | 振替     | 支払元と入金先       | なし | 1 件。メモ・金額                                               |
  | 残高調整 | 支払元か入金先の片方 | なし | 1 件。メモ・金額                                               |

- 種類は変えられない。変えたいときは消して登録し直す（収入・振替の新規登録は今回は作らないので、当面は種類を変える必要が出たら CLI で直す）
- 店舗は既存の店舗から選ぶか、名前を入れる。完全に一致する店舗がなければ作る（拡張機能の登録と同じ）
- 支出の品目は足す・消す・並べ替えができる。金額は負も受け付ける（値引き）
- 保存は名前付きアクション `update`。取引の更新・品目の総入れ替え（消してから入れ直す）・店舗の作成を 1 回の `db.batch` にする。品目ごとの差分は取らない
- 削除は名前付きアクション `delete`。確認のダイアログを出してから消し、一覧へ戻る。品目は外部キーの `on delete cascade` で消える
- 保存したら `updated_at` が変わる。`source`（`manual` / `zaim_csv`）は変えない

### 口座の残高（`/accounts`）

`/accounts?date=YYYY-MM-DD`。`date` がなければ今日（日本時間）。

- アーカイブしていない口座ごとに、その日の終わりの残高を出す。残高 0 で直近 1 年に動きのない口座は「使っていない口座」として畳む
- 残高の合計
- 口座を押すと、その口座で絞り込んだ取引の一覧へ移る

残高のきまり：

- 口座の残高 ＝ その口座が `to_account_id` の取引の金額の合計 − `from_account_id` の取引の金額の合計（日付が `date` 以前のもの）。取引の金額は品目の金額の合計
- 種類を問わずすべて入れる（支出・収入・振替・残高調整）。`aggregation` は残高には関係しない
- フェーズ1の CSV の取り込みで残高調整を差額として入れたので、これで Zaim の残高と一致するはず。実装したら Zaim の画面の残高と口座ごとに比べて確かめる

## 決めたこと

- **Zaim から取り込んだ取引も編集できる。ただし直すのは切り替えの後にする。** 切り替える日の再取り込みで `source = 'zaim_csv'` の取引は総入れ替えになるので、それより前に直した内容は消える。画面では止めない（自分しか使わないので、手順で守る）
- **画面の変更はページのアクションで受け、`/api/*` には足さない。** `/api/*` は拡張機能のための API として、拡張機能が使う分だけを持つ
- **収入・振替・残高調整の新規登録は今回は作らない。** Zaim で記録していた分は切り替え時に CSV で入る。切り替えた後に必要になったら足す
- **マスタ（口座・カテゴリ・内訳・店舗）の名前の変更・統合・アーカイブの画面は今回は作らない。** フェーズ1で決めたとおり、マスタの整理は切り替えの後にやる
